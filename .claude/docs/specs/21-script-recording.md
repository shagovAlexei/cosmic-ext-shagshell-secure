# 21. Запись скрипта (Script → Start Recording)

SecureCRT записывает действия в терминале в скрипт. Делаем так же: включили запись, поработали в терминале, остановили, сохранили `.py`.

## Что
- **Script → Record Script** (галочка; тот же пункт останавливает запись; функция `ToggleRecording` есть в Button Bar и Key Map), пока идёт запись — в строке состояния «● ЗАПИСЬ СКРИПТА». Пишется **активная вкладка-терминал**; одновременно одна запись.
- **Что попадает в скрипт:** набранный текст и вставка из буфера → `crt.Screen.Send("…")`; каждый Enter завершает шаг. Перед каждым шагом — `crt.Screen.WaitForString("<последняя строка вывода>")` (то, что сервер показал перед вводом: приглашение), если она непустая; длиннее 80 символов — по её последним 40. Приглашение на экране в момент старта записи — приглашение первого шага. Спец-клавиши — управляющими последовательностями (`\x03` Ctrl+C, `\t`, `\x1b[A` и т. д.); Backspace правит набираемую строку, а не записывается.
- **Пароли не пишутся.** Если последняя строка вывода — запрос пароля / passphrase (`core::askpass::classify`), шаг записывается как `crt.Screen.Send(crt.Dialog.Prompt("<запрос>", "Password", "", True) + "\r")`: пароль скрипт спросит при запуске.
- **Stop Recording** → системный диалог «Сохранить как…» (`.py`); отмена — запись выбрасывается. Файл: шапка-комментарий (дата, вкладка), `crt.Screen.Synchronous = True`, шаги; запускается как любой скрипт.
- Закрытие вкладки во время записи останавливает её и спрашивает, куда сохранить то, что есть.

## Как
- `core::recorder::Recorder`: `output(text)` (последняя строка вывода), `input(bytes)` (набираемая строка, Backspace, спец-клавиши, шаги), `script(header)` → текст `.py`. Чистая логика, тесты на: шаги и ожидания, Backspace, спец-клавиши, длинное приглашение, пароль → Prompt, экранирование кавычек и юникода, пустой ввод.
- Приложение: `Tap` получает `recorder: Arc<Mutex<Option<Recorder>>>`; вывод идёт через `Cleaner` (как лог / `script::Buffer`), ввод — из места, где терминал пишет в PTY. Меню и состояние в `script.rs` / `menu.rs`.

## Не делаем
- Запись мыши, изменений размера, нескольких вкладок, команды из Command Window (только то, что набрано в терминале).
- Умные паузы между шагами: ожидания по приглашению достаточно.

## Проверка
- Тесты `core`. Headless: записать «ls», «echo hi» в локальном shell, сохранить, запустить сохранённый скрипт. Меню в headless не кликается — старт / стоп проверяются через кнопку Button Bar или ключ (Menu Function), диалог сохранения — вручную.
