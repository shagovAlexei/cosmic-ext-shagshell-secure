# 09. Logon Actions, подсветка, цветовые схемы, импорт из SecureCRT

Этап делится на три PR:
- **9a** — Logon Actions (этот документ).
- **9b** — подсветка ключевых слов и цветовые схемы терминала.
- **9c** — импорт сессий из SecureCRT (`.ini` / экспорт), в том числе кнопок Button Bar (см. бэклог).

## 9a: Logon Actions

Session Options → «Действия при входе» (`[[logon]]` в файле сессии: `expect`, `send`).
- После подключения программа сессии (ssh, telnet, picocom, shell) читается: когда вывод содержит текст `expect` (без учёта регистра; escape-последовательности терминала убраны, видна и недописанная строка — приглашение без `\n`), отправляется `send`; строки идут по порядку, один показ текста отвечает одной строке. Пустой `expect` — отправить сразу.
- `send`: escapes `\r \n \t \e \p` (`core::macros`); `%user%` — пользователь сессии; `%password%` — пароль сессии из keyring.
- **Пароль в файл не пишется.** Поле «Пароль для %password%» на этой странице уходит при OK прямо в keyring (`kind=session, secret=password`, тот же, что сохраняет диалог ssh), пустое — оставляет сохранённый. Нет пароля — ответ не отправляется, в строке состояния сообщение. Писать пароль прямо в `send` можно, но он окажется в файле сессии: так делать не стоит.
- Работает для любых протоколов (телнет и serial — основной случай: «Username:» → `%user%`, «Password:» → `%password%`, «#» → `terminal length 0`); при Reconnect / Clone — снова.
- Устройство: `core::logon` (автомат, `Cleaner` из логов, подстановка), `app::term::log::Tap` (читатель PTY отдаёт вывод автомату, ответ идёт во вход PTY через `EventLoopSender`; пароль достаётся из keyring в отдельном потоке).

### Мои решения (проверь)
- Подстрока без регистра, а не регулярное выражение (SecureCRT тоже без).
- Нет тайм-аута: строка ждёт сколько нужно; сбросить — Reconnect.
- Нет галки «Hide» (в SecureCRT скрывает строку при вводе): пароль не показывается, потому что идёт из keyring.

## 9b: подсветка ключевых слов и цветовые схемы

- **Цветовые схемы терминала:** 8 встроенных (Solarized Dark / Light, Dracula, Nord, Gruvbox Dark, Monokai, Classic, Tango Light; палитры в `term/terminal_theme.rs`). Options → Global Options → «Цвета терминала» → «Цветовая схема» (по умолчанию «Системная» — тема COSMIC, как раньше); у сессии свой выбор: Session Options → «Внешний вид» (поле `color_scheme`), пустой — глобальный. Применяется сразу ко всем открытым вкладкам.
- **Подсветка ключевых слов:** правила в `~/.config/shagshell/highlights.toml` (`[[rule]] text, colour, background`), правятся в Global Options (слово, цвет из 8, «заливка», корзина, «Добавить слово»), переключатель «Подсветка ключевых слов». Слово (без учёта регистра) в видимом выводе красится цветом буквы или заливкой фона; при пересечении выигрывает правило выше в списке. Это только раскраска экрана: текст, логи, буфер обмена не меняются; жирный / подчёркивание у закрашенных слов не сохраняются.
- Общий для всех сессий набор слов (у SecureCRT — наборы на сессию; позже). Файл, который не прочитался, не перезаписывается (ошибка в строке состояния).

### Мои решения (проверь)
- Слова только подстрокой, без регулярных выражений и «целого слова».
- 8 цветов вместо произвольного RGB (читаются и на тёмной, и на светлой теме).
- Известные ограничения: слово, разорванное переносом строки терминала, не находится (поиск по строке экрана); регистр не важен только для латиницы; в ячейках с обратной раскраской (поиск в `less`, строки `htop`) подсветка перекрывает их цвет.

## 9c: импорт из SecureCRT

File → «Импорт из SecureCRT…» (диалог): папка `Config` (находится сама под wine: `~/.wine/drive_c/users/*/AppData/Local/VanDyke Software/SecureCRT/Config`, см. `securecrt-reference.md`; есть «Обзор…»), галочки «Сессии» и «Button Bar», отчёт в диалоге. Работа — `core::securecrt::import` в фоне (на реальном конфиге 1200+ файлов).

- **Формат** (разобран по настоящим файлам): `.ini` — строки `S:"Имя"=текст`, `D:"Имя"=hex` (dword), `Z:"Имя"=n` + n строк с пробелом в начале (список), `B:` — двоичные (пропускаются).
- **Сессии** (`Sessions/**.ini`, папки = папки; `Default*.ini` и `__FolderData__.ini` — не сессии): `Protocol Name` SSH2 / Telnet / Local Shell / Serial → наши протоколы, RDP и прочее — пропуск с отчётом; `Hostname`, `[SSH2] Port` / `Port` (22 / 23 — по умолчанию, не пишутся), `Username`, `Identity Filename V2`; `Firewall Name` вида `Session:<путь>` → `jump` (`user@host:port` той сессии); Serial: `Com Port` (`COM3` → `/dev/ttyS2`, предположение) и `Baud Rate`; лог: `Start Log Upon Connect` + имя файла из `Log Filename V2` (шаблон `%H %S %Y %M %D %h %m %s` тот же; папка Windows отбрасывается), `Log Mode` 1 = дописывать, `Raw Log`; `User Button Bar Name` → `button_bar`, если такая панель есть (импортирована сейчас или раньше). Уже существующее имя не трогается.
- **Button Bar** (`ButtonBarV5.ini`): `Z:"панель"=n` + n строк ` KIND,поле,поле,,подпись,0,n,подсказка,`; поля через запятую, `\,` — запятая, `\\` — обратная косая, `\r` / `\n` — настоящие символы; сама строка Send String хранится с её escape-последовательностями (`\\n` в файле = `\n`, тот же язык, что у `core::macros`). `SEND` → «Отправить строку» (в текущую вкладку; подпись — поле 2, пусто — начало строки); `RUN` и прочее — в отчёт (скрипты — фаза 10). Панель `---` (разделитель) пропускается; панели с уже существующим именем не перезаписываются.
- **Не переносится:** пароли и строки скрипта входа (зашифрованы SecureCRT), RDP, цветовые схемы SecureCRT, пробросы портов (в реальных файлах не встретились, формат не проверен), горячие клавиши кнопок.
- Проверено на настоящем конфиге пользователя: 1207 сессий (1202 SSH2, 5 Local Shell), 24 панели, 279 кнопок Send String, 24 кнопки Run Script — пропущены. Образцы не копируются в репозиторий (хосты и пути настоящие): тесты на синтетических файлах; `live_config` (`SECURECRT_CONFIG=… cargo test -- --ignored`) печатает только числа.
