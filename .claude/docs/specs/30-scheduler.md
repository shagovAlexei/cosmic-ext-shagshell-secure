# 30. Планировщик скриптов

Запуск скриптов по расписанию, пока приложение открыто. Ветка `feat/scheduler` (от `feat/crt-more`), версия 0.41.0.

## Что
- Script → «Планировщик…»: окно со списком задач (включена, имя, скрипт, расписание, последний запуск) и кнопками Добавить / Изменить / Удалить / Запустить сейчас.
- Задача: имя, путь к `.py`, аргументы, расписание — **каждые N минут** или **каждый день в HH:MM**, флажок «включена».
- Файл `~/.config/shagshell/schedule.toml` (неизвестные поля сохраняются; битый файл не перезаписывается).
- Запуск — как pre-script: **без вкладки** (`crt.Screen` недоступен; `crt.GetTab(n)`, `crt.Session.Connect`, `crt.Dialog`, `os`, `subprocess` работают), тихо: консоль сама не открывается, вывод и ошибки — в Script Console и `script.log`. Итог — строка состояния.
- Задача, чей прошлый запуск ещё идёт, пропускается (не копятся). Пропущенное, пока приложение было закрыто, не догоняется. «Каждые N минут» отсчитывается от старта приложения / сохранения задачи.
- Тик раз в 15 секунд; расписание — чистая функция в `core`.

## Как
- `core::schedule`: `Job {name, script, args, every: Every::{Minutes(u32), Daily(h,m)}, enabled}`, `Schedule` (load/save, rows), `due(job, last_run, now) -> bool` (тесты: интервал, суточное время, не дважды в минуту, отключена, переход через полночь).
- App: `scheduler.rs` (окно, `SchMsg`), подписка-тик, запуск через `Scripts::run` с вкладкой-заглушкой `u64::MAX` (как pre-script); id запуска → снимается с «идёт» по `Outcome.ended`.
- Строки `fl!` en+ru, TESTING.md, пример `Example/16_scheduled.py`.

## Не делаем
- Запуск при закрытом приложении (cron / systemd timer); календарь по дням недели; запуск на вкладке сессии.
