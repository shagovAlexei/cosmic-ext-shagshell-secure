# 05. SFTP-вкладка

## Зачем

SecureCRT открывает к сессии «Connect SFTP Tab», SecureFX даёт две панели и очередь передач. Пользователь — человек коммандера (shagoff commander): две панели, Tab, F5–F8. Делаем SFTP-вкладку как коммандер: слева локальные файлы, справа сервер, внизу очередь.

Этап делится на два PR:
- **5a** — вкладка, обе панели, навигация, F5 копировать / F6 перенести / F7 папка / F8 удалить / Shift+F6 переименовать, отметки, очередь передач (прогресс, скорость, отмена, повтор), вопрос при перезаписи, перетаскивание между панелями.
- **5b** — докачка, правила перезаписи (всегда / только новее / пропустить, «для всех»), перетаскивание из файлового менеджера и в него, chmod, правка удалённого файла локально, закладки.

## Как открывается

- Меню вкладки «Connect SFTP Tab», кнопка SFTP на тулбаре, Transfer → Connect SFTP Tab, Alt+P — для сессии активной вкладки; ПКМ по сессии в дереве → «Открыть SFTP».
- Новая вкладка в той же группе, заголовок «SFTP · <имя сессии>», в статус-баре «SFTP · host».
- Соединение: `ssh <опции сессии> -o ControlMaster=auto … -s -- host sftp` — тот же ControlPath, что у терминала: открытое соединение используется без пароля; если его нет — ssh подключается сам, пароль / ключ хоста — нашими диалогами askpass. Логин набора учётных данных — как у терминала.
- Соединение оборвалось — панель сервера пишет причину, кнопка «Переподключить» (и Enter, как у терминала).

## Вкладка

```
 [✓ web-01] [SFTP · web-01]
 ┌ /home/shag ───────────────────┐┌ web-01:/var/www ──────────────┐
 │ ..                            ││ ..                            │
 │ [Documents]          <DIR>    ││ [html]               <DIR>    │
 │ notes.txt      1.2 KB 10:31   ││ index.php      4.1 KB вчера   │
 └───────────────────────────────┘└───────────────────────────────┘
 Очередь: ▶ index.php → /home/shag   45%  3.1 MB/s  0:04   [Отмена]
          ✓ notes.txt → /var/www          готово
          ✗ big.iso → /var/www    Permission denied     [Повтор]
```

- Панель: путь сверху (клик — ввод пути), колонки имя / размер / дата, папки сверху, сортировка по имени (клик по заголовку — по колонке), `..` вверху.
- Клавиши (как в shagoff commander): ↑↓ PgUp PgDn Home End, Enter — войти / `..` — выше, Backspace — выше, Tab — другая панель, Insert / пробел — отметить, Ctrl+A — все, F5 копировать в другую панель, F6 перенести, Shift+F6 переименовать, F7 новая папка, F8 / Delete удалить (подтверждение), Ctrl+R — обновить. Клавиши вкладки (Ctrl+Tab, Alt+1…9, Ctrl+Shift+W) работают как везде.
- Мышь: клик — курсор, Ctrl / Shift — отметки, двойной клик — войти, перетаскивание отмеченного на другую панель — копировать (с Shift — перенести).
- F5 / F6 спрашивают «Копировать N файлов в <путь>?» с полем пути (как в коммандере).

## Очередь передач

- Каждая передача — строка: направление, имя, куда, прогресс, скорость, осталось; состояния ожидает / идёт / готово / ошибка / отменено. Папки — рекурсивно (дерево раскладывается в файлы).
- Идёт одна передача за раз на вкладку (по одному SFTP-каналу; конвейерные запросы — скорость не страдает).
- Файл уже есть в цели — диалог: Перезаписать / Пропустить / Отмена, галочка «Для всех» (на эту операцию). Правила «только новее» / докачка — 5b.
- Отмена — текущий файл недокачан: удаляем недописанный. Повтор — с начала.
- Перенос (F6) = копирование, потом удаление источника, только если файл скопирован целиком.
- Готовые строки остаются до «Очистить готовые».

## Устройство

- **`core::sftp::proto`** — свой клиент SFTP v3 (draft-ietf-secsh-filexfer-02, как у OpenSSH): INIT / VERSION, REALPATH, OPENDIR / READDIR / CLOSE, STAT / LSTAT, OPEN / READ / WRITE (несколько запросов в полёте), MKDIR / RMDIR / REMOVE / RENAME. Имена — байты (`OsString`): имена не в UTF-8 показываются (как в коммандере, с заменой) и работают.
  - Почему свой, а не `openssh-sftp-client`, как было в архитектуре: спайк показал, что имя файла не в UTF-8 роняет его соединение целиком (`ssh_format` разбирает путь через `String::from_utf8`), а чтение без конвейера даёт 15 МБ/с против 190 на запись.
  - Тесты — против настоящего `/usr/lib/openssh/sftp-server`, запущенного напрямую (без ssh).
- **`core::sftp::queue`** — очередь как чистая машина состояний (из архитектуры): разложить отмеченное в задания, следующий шаг, прогресс, конфликты, отмена, повтор.
- **`core::panel`** — список, курсор, отметки, сортировка, форматирование размеров и дат (по образцу shagoff commander, `crates/core/src/panel.rs` / `format.rs`, урезанно).
- **`app::sftp_view`** — вкладка: две панели, очередь, диалоги; ввод-вывод — в отдельном потоке на вкладку (команды → поток → события), UI не ждёт сеть.
- Вкладка — новый вид в `tabs` (у вкладки «терминал» или «SFTP»), группы, перетаскивание, закрытие — общие.

## Мои решения (проверь)

- Свой SFTP-клиент вместо `openssh-sftp-client` (причина выше).
- Одна передача за раз на вкладку; параллельные — позже, если понадобится.
- Локальная панель — обычные файлы через `std::fs`, без gvfs.
- Скрытые файлы показываются (как `ls -a`); переключатель — 5b.
