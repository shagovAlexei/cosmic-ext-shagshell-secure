# 13. Синхронизация папок в SFTP

SecureFX: Synchronize Folders с предпросмотром различий. В SFTP-вкладке (`Ctrl+Y`, и кнопка «Синхронизировать…» в строке подсказок) открывается диалог для папок, которые сейчас открыты в левой (локальной) и правой (серверной) панелях.

## Порядок работы
1. **Параметры:** направление — «На сервер» (локальная → сервер), «С сервера» (сервер → локальная), «Двусторонняя» (новее побеждает); «С вложенными папками» (по умолчанию да); «Удалять лишнее в приёмнике» (зеркало; только для односторонних; по умолчанию нет).
2. **«Сравнить»:** воркер читает оба дерева (рекурсивно, ссылки не раскрываются, как при копировании) и `core::sftp::sync::diff` выдаёт список действий: копировать (новый файл / файл новее / другой размер) и, если включено зеркало, удалить лишнее. Файлы равны, если совпадает размер и время изменения отличается не больше чем на 2 с (в SFTP v3 время целое, секунды).
3. **Предпросмотр:** таблица «действие · путь · размер», у каждой строки галочка (по умолчанию все), итог «N файлов, M МБ, K удалений». Пусто — «Папки одинаковы».
4. **«Выполнить»:** копирования идут в обычную очередь передач одной пачкой с заранее данным ответом «перезаписать» (вопросов «файл существует» нет); недостающие папки создаются перед пачкой. Удаления (зеркало) выполняются воркером после того, как пачка скопирована без ошибок, и перед этим спрашивается подтверждение с числом удаляемых файлов.
5. После каждого скопированного файла **время изменения приёмника ставится равным времени источника** (SFTP `setstat` / `File::set_modified`): иначе повторная синхронизация видела бы всё как изменённое.

## Мои решения (проверь)
- Двусторонняя синхронизация никогда ничего не удаляет; файл, которого нет на одной стороне, копируется на неё (удалённые файлы так «воскреснут» — это ограничение без базы прошлого состояния).
- Если и там и там есть, но одно — файл, а другое — папка: строка предупреждения, ничего не делается.
- Фильтров и масок нет (всё дерево), расписания нет, символические ссылки пропускаются.
- Предпросмотр строится один раз; если файлы поменялись между «Сравнить» и «Выполнить», очередь отработает по списку (перезапись безусловная) — при сомнении нажмите «Сравнить» ещё раз.

## Устройство
- `core::sftp::sync`: `Node { rel, size, mtime, is_dir }`, `Mode`, `Op { kind: Up / Down / DeleteLocal / DeleteRemote / Conflict, rel, size }`, `diff(local, remote, mode, mirror) -> Vec<Op>` — чистая функция, тесты на все ветки (новый, новее, размер, допуск 2 с, зеркало, двусторонняя, файл против папки).
- Воркер просмотра: `scan(local_root, remote_root, recursive)` → два списка `Node`.
- `ops::transfer` дополняется установкой времени (общая для обычных копирований: сохранение времени источника, как у SecureFX «preserve times»).
