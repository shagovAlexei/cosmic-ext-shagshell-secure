# 08. Jump host, проброс портов, автопереподключение, Telnet / Serial

Этап делится на два PR:
- **8a** — всё про ssh (этот документ): jump host, проброс портов, автопереподключение.
- **8b** — протоколы Telnet и Serial (`telnet host port`, `picocom -b … dev`) в Session Options → «Протокол».

## 8a
- **Jump host** (Session Options → SSH2 → «Промежуточный хост», поле `jump`): `[user@]host[:port]`, несколько через запятую → `ssh -J …`. Ключ jump-хоста — из ssh-agent / `~/.ssh` (ssh не даёт отдельный `-i` для `-J`); пароль jump-хоста спрашивается диалогом, в keyring не сохраняется (так сделано в 4a). SFTP-вкладка сессии идёт через тот же jump.
- **Проброс портов** (категория «Проброс портов», `[[forward]]` в файле сессии: `kind` local / remote / dynamic, `listen` = `[адрес:]порт`, `host`, `port`) → `-L / -R / -D`. Строки добавляются / удаляются кнопками, проверяются порты и хост (`core::session::form`). У SFTP-вкладки проброс отключён (`ClearAllForwardings`).
- **Автопереподключение** (SSH2: флажок, секунды до него — 5, попыток подряд — 10; `reconnect*` в файле): когда ssh завершился кодом 255 (соединение потеряно), вкладка не закрыта и не отключена кнопкой Disconnect, и соединение держалось ≥ 10 с (или уже идёт серия попыток) — через заданное время программа запускается снова, в терминале видно «соединение потеряно — переподключение через N с (попытка k из M)». Серия кончается, когда попытки вышли или соединение продержалось ≥ 10 с. Неудачный первый вход (неверный пароль, хост недоступен) не повторяется сам.

### Мои решения (проверь)
- Jump — текстом, не выбором из сохранённых сессий (SecureCRT выбирает сессию-файрвол); ключ jump-хоста отдельно задать нельзя.
- Проброс — только в окне настроек, без «включить на ходу» (`~C`).
- Известные ограничения: ssh выходит с кодом 255 и при неудачном входе после долгого ожидания диалога (неверный пароль через >10 с) — тогда серия повторов может начаться и использовать сохранённый пароль до «попыток подряд» раз (по умолчанию 10; для аккаунтов с блокировкой поставь 1–2). Клон и Reconnect при живом ControlMaster повторно просят тот же проброс — ssh сообщит «Address already in use» (мастер уже слушает порт).
- Логика решения о повторе — `core::reconnect::next_attempt` (тесты).
