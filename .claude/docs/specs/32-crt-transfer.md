# 32. crt.FileTransfer и Session.Lock (фаза 29b)

Ветка `feat/crt-transfer` (поверх `feat/ui-polish`), версия 0.44.0.

## Что
| Вызов | Поведение |
|---|---|
| `crt.FileTransfer.Upload(local, remote="")` | файл или папка с компьютера на сервер вкладки; `remote` пусто — домашняя папка сервера под тем же именем, `remote` с `/` на конце или существующая папка — внутрь, иначе — новое имя |
| `crt.FileTransfer.Download(remote, local="")` | с сервера на компьютер; `local` пусто — `~/Downloads` (как Zmodem); тот же разбор «папка / имя» |
| `crt.Session.Lock()` / `Unlock()` | вкладку нельзя печатать и вставлять вручную (клавиши и вставка пользователя), скрипт по-прежнему шлёт `Send`; в заголовке вкладки замок; `crt.Session.Locked` — состояние |

- Передача идёт по SFTP через то же ssh-соединение вкладки (ControlPath, как «Connect SFTP Tab»): пароль не спрашивается, если соединение открыто. Вкладка без ssh (Local, Telnet, Serial, SFTP) — ошибка «нет SFTP для этой вкладки».
- Вызов блокирует скрипт, пока файл не передан (как в SecureCRT). Существующий файл заменяется (SecureCRT на скриптовой передаче не спрашивает); целая папка копируется рекурсивно. Ошибка (нет файла, права, обрыв) — `crt.ScriptError` с текстом; успех — `True`.
- Замок снимается сам, когда кончается запуск, который его поставил (упавший скрипт не оставляет вкладку заблокированной). Вкладка закрыта — замка нет.

## Как
- `core::sftp::ops` уже умеет `plan` + `transfer` над `Client`; в `core::script` — разбор путей `target_path(local_or_remote, name, is_dir_hint)` (чистая функция, тесты: пусто / `/` на конце / имя / `~`).
- app: `script::answer` не годится (блокирует UI): вызов идёт в потоке надзирателя запуска (как `Dialog.*`, там уже есть работа вне UI-потока): `ssh <sftp_args вкладки> -s -- host sftp` → `Client` → `plan` → `transfer` с `Choice::Overwrite`; процесс ssh закрывается в конце вызова. `Host::ui` получает `FileTransfer.Upload/Download` и отвечает из этого потока; `Tabs::sftp_launch(tab)` отдаёт argv вкладки (уже есть `Launch::sftp`).
- Замок: `Terminal::locked: AtomicBool`; `input_no_scroll` / `paste` от пользователя его проверяют, `Tap` (ввод скрипта) — нет. `Scripts` помнит `HashMap<run, Vec<TabId>>`; `Outcome.ended` снимает. Заголовок вкладки: `🔒`.
- `crt.py`: `FileTransfer` и `Session.Lock/Unlock/Locked` — тонкие обёртки.
- Пароли и ключи сюда не попадают (ssh сам, через askpass как обычно); путь и текст ошибок без секретов.

## Не делаем
- Прогресс-окно и очередь (скрипт ждёт; прогресс в консоль не пишем);
- ZModem / XModem из скрипта (`FileTransfer` по SFTP);
- маски `*.log` в `Upload` (одним вызовом — один файл или папка; цикл в Python).

## Проверка
- `core`: тест разбора путей; существующие тесты `sftp::ops`.
- `just verify`; headless: `Example/17_transfer.py` (Upload / Download туда-обратно с локальным sshd из `headless.sh`, сверка содержимого), скрипт с `Lock` — печать в заблокированной вкладке не доходит, `Send` доходит, после конца скрипта печать работает.
