# 36. Конструктор скриптов (Script Builder)

Скрипт для `crt` собирается из блоков мышью, без набора Python. Любой `.py` открывается в конструкторе блоками, правка блоков или кода — в обе стороны. Идея пользователя, brainstorm 2026-10-26 / 27.

## Зачем

Обычный пользователь (не программист) решает типовые задачи админа:
1. в открытой сессии выполнить команду, вывод — в буфер обмена;
2. подключиться к хостам из файла, выполнить там команды, результаты — в файл;
3. список серверов × список команд: все серверы открываются параллельно, на каждом выполняются все команды, **у каждого сервера свой лог-файл**.

Код таких скриптов уже есть (`Example/04`, `06`, `08`), но это 30–60 строк с хитрым ожиданием приглашения. Конструктор даёт собрать то же самое за минуту.

## Цели
- Палитра со **всеми** командами `crt` блоками + крупные блоки для типовых задач; к каждому — шпаргалка по параметрам.
- Любой `.py` (свой, из `Example/`, из SecureCRT) открывается блоками; что не распознано — блок «Свой Python», ничего не теряется.
- Окошко с готовым кодом: копировать и **править**, блоки следуют за кодом.
- Запуск из конструктора с подсветкой блоков и отладкой (точки остановки, шаг, переменные); всё это отключается галочками.
- Шаблоны: готовые (три сценария выше + `Example/`) и свои.
- Script → Record Script сразу открывает запись в конструкторе.

## Анти-цель
**Нагромождённый интерфейс** (главное, что заставит поморщиться). Отсюда:
- по умолчанию видно только: панель кнопок, палитра (раскрыт раздел «Частые», группы `crt` свёрнуты), лента, шпаргалка (одна строка «что делает», полная — по ▸), код свёрнут в полоску «Код ▸»;
- кнопки отладки и панель «Переменные» появляются только во время запуска / на паузе;
- на блоке — только его поля; редкие параметры (флажки «без учёта регистра» и т.п.) — под «ещё ▸» на самом блоке;
- никаких плавающих окон: всё внутри вкладки.

## Не делаем
- Свободный холст, как в Scratch: только вертикальная лента.
- Сохранение оформления ручного файла: при сохранении код пишется заново из блоков (решение пользователя, «вариант 1»: кавычки, переносы, пустые строки — «как у конструктора»; смысл и комментарии сохраняются).
- Классы, декораторы, `async`, генераторы как блоки — только «Свой Python».
- Отдельный файл `.blocks.json`: источник блоков — сам `.py`.

## Как выглядит

Вкладка (`tabs::Body::Builder`, как заметка: в полосе вкладок и группах, можно в своё окно; значок по `tab_icon`). Открыть: Script → «Конструктор скриптов…» (новый пустой), Script → «Открыть в конструкторе…» (выбор `.py`), действие `ScriptBuilder` для клавиши / кнопки; правый щелчок по скрипту в Script menu — «Открыть в конструкторе» (по усмотрению строителя, если меню скриптов это позволяет без перекройки).

```
┌ Панель: Новый · Из шаблона ▾ · Открыть · Сохранить · Сохранить как шаблон │ на: [вкладка ▾] ▶ Запустить │ ⚙ ┐
├──────────── палитра ───────┬──────────────── лента ─────────────────────────────┤
│ 🔍 поиск                    │ Прочитать список ~/servers.txt → хосты             │
│ Частые                      │ Для каждого хоста из хосты  ☑ параллельно          │
│   Выполнить команду         │ ┊ Лог в файл ~/logs/%S_%Y%M%D.log                  │
│   Для каждого хоста         │ ┊ Для каждой команды из команды                    │
│   …                         │ ┊ ┊ Выполнить команду {команда} ждать 30 с          │
│ ▸ Screen ▸ Session ▸ Dialog │ ┊ Отключиться                                      │
│ ▸ Прочее                    │ Сообщение «Готово»                                 │
│ ── шпаргалка выбранного ──  │                                                    │
├─────────────────────────────┴────────────────────────────────────────────────────┤
│ Код ▸   (развёрнутый: редактор, Копировать всё)                                    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **Палитра:** поиск по имени и описанию (en + ru). Разделы: «Частые» (крупные блоки), группы `crt` (Screen, Session, Dialog, Tab, Window, Clipboard, FileTransfer, Arguments, crt — `Sleep`, `GetTab`, `Quit`…), «Прочее» (переменная, если / иначе, повторить N раз, для каждого, пока, попытка / ошибка, функция, вызвать функцию, пауза, комментарий, сообщение, Свой Python, import, return / break / continue).
- **Добавить блок:** перетащить из палитры в ленту (между блоками или внутрь «если / повторить / функции»), двойной щелчок — в конец ленты (или в конец выбранного вложенного блока). Внутри ленты: перетаскивание, Delete — удалить выбранный, Ctrl+C / Ctrl+V — копировать блок (с вложенными), Ctrl+Z / Shift+Ctrl+Z — отмена / повтор. Вложенность — отступом и пунктирной линией слева.
- **Поля на блоке:** у каждого параметра тип (текст, число, флажок, выбор из списка, имя сессии, файл, переменная). Переключатель «текст / выражение» (`"show ver"` против `cmd + "\r"`): в режиме выражения поле принимает Python-выражение как есть. Ошибка в поле (не число, пустое обязательное) — блок с красной рамкой и текстом ошибки, «Запустить» и «Сохранить» недоступны, пока ошибки есть.
- **Шпаргалка:** при наведении на блок (в палитре или ленте) — всплывающая подсказка; под палитрой — панель о выбранном блоке. Текст один: что делает, параметры (тип, по умолчанию, смысл), что возвращает, пример строки Python. Язык — интерфейса.
- **Код:** редактор заметок (`editor/`, подсветка Python, номера строк). Обновляется при каждом изменении блоков. Правка кода: через 1 с после последнего нажатия код разбирается и лента перестраивается; синтаксическая ошибка — блоки прежние, строка подсвечена, под кодом «строка 12: …», запуск / сохранение недоступны. Выбран блок — его строки подсвечены в коде; щелчок по строке кода выбирает её блок. Кнопка «Копировать всё».
- **⚙** (галочки, хранятся в Config, все вкл. по умолчанию): «Подсветка выполнения», «Значения на блоках», «Остановки и шаги».

## Запуск и отладка
- «на: [вкладка ▾]» — список открытых терминалов + «без вкладки»; по умолчанию — терминал, активный последним перед конструктором. Скрипт запускается как обычный (`script.rs`, `SHAGSHELL_SCRIPT_TAB` = выбранная вкладка), из временного файла, если не сохранён.
- Во время работы блоки в ленте: выполняется — синяя рамка; выполнен — зелёная полоса; ошибка — красный, на блоке текст ошибки; не дошли — серый. «Значения на блоках»: последний результат («вывод: 14 строк ▸», по щелчку текст). Параллельный блок: счётчик по хостам «✓ 2 ✗ 1 ⏳ 0», по щелчку — какой хост где.
- Отладка: щелчок слева от блока — точка остановки (красная точка; хранятся только в открытой вкладке, в файл не пишутся). Кнопки во время запуска: Пауза, Шаг, Продолжить, Стоп. На паузе — панель «Переменные» (имя → значение, `repr` обрезан до строки). Пауза в параллельном режиме останавливает все хосты.
- Механика: код сгенерирован конструктором → известна карта «строка → блок». В режиме отладки `crt.py` ставит `sys.settrace` и шлёт приложению по сокету `crt` событие «строка N» (новые вызовы протокола `core::script`, напр. `Trace` / `Break`); на точке остановки или в пошаговом режиме ждёт ответа «продолжить». Всё выключено → обычный запуск без `settrace`.
- Script Console работает, как и для обычных скриптов.

## Крупные блоки и `shag_blocks.py`
- Крупные блоки генерируются в вызовы библиотеки `res/python/shag_blocks.py` (вшита в программу, `core::bundled` кладёт её в `~/.config/shagshell/scripts/shag_blocks.py` — рядом со скриптами — и переписывает, если отличается; в меню Script её не показывать), например:
  - `out = run(tab, "show ver", timeout=30)` — отправить, дождаться приглашения (логика `wait_for_prompt` из `Example/04`), вернуть вывод без эха и приглашения;
  - `hosts = read_list("~/servers.txt")` — строки файла без пустых и `#`;
  - `for tab in each_host(hosts, parallel=True):` — подключиться (`Session.Connect /S`), выполнить тело, отключиться; хост, который не подключился, — в итоговый список ошибок, остальные продолжают;
  - `log_to(tab, "~/logs/%S_%Y%M%D.log")` — свой лог у вкладки (шаблоны имени как у `core::logfile`);
  - `append_file(path, text)`, `to_clipboard(text)`.
- Разбор узнаёт эти вызовы и показывает их снова крупными блоками.
- Параллельно одновременно — не больше N хостов (поле на блоке, по умолчанию 10), остальные ждут очереди.
- Следствие (решение пользователя: библиотека рядом, а не функции внутри скрипта): такой скрипт в SecureCRT запустится, только если `shag_blocks.py` положить рядом. Скрипт только из блоков `crt` от него не зависит (`import shag_blocks` пишется лишь при надобности).
- **Параллельно:** тело `each_host(..., parallel=True)` выполняется в потоке на хост. `crt.py` сейчас — одно соединение и блокирующий `_call`; нужно соединение на поток (`threading.local`) и приём нескольких соединений одного запуска в `core::script::serve` / `script.rs`. Строитель проверяет и выбирает, как именно.

## Часть 3: как сделано (2026-10-27)
- **«Для каждого хоста»** — блок `Block::ForHost { hosts, func, parallel, limit, body }`; в коде это функция и её вызов (настоящий Python, работает и без конструктора):
  ```python
  def _host_1(tab, host):
      ...тело...
  each_host(hosts, _host_1, parallel=True, limit=10)
  ```
  `shag_parse.py` узнаёт пару «`def _host_N(tab, host)` + сразу за ней `each_host(<список>, _host_N, …)`» и отдаёт один блок; иначе — обычные `def` и вызов. Внутри тела `tab` — вкладка хоста, `host` — его имя.
- Параллельно: `each_host` запускает тело в потоке на хост (не больше `limit` сразу); `crt.py` держит соединение с программой на поток (`threading.local`), программа принимает несколько соединений одного запуска.
- Остальные крупные блоки — функции `shag_blocks.py` в каталоге (группа `blocks`, тест сверяет с модулем): `run(tab, cmd, timeout)`, `read_list(path)`, `log_to(tab, template)`, `append_file(path, text)`, `to_clipboard(text)`. Первый такой блок вставляет в начало скрипта строку `from shag_blocks import *` (обычный блок «Свой Python», её видно).
- `shag_blocks.py` пишется в `~/.config/shagshell/scripts/` (`core::bundled`, переписывается, если отличается; в меню Script не показывается). `crt.py` добавляет в путь импорта папку скрипта и `scripts/`.
- Шаблоны: `scripts/templates/*.py` (три сценария из «Зачем» кладутся, если их нет) и `scripts/examples/*.py`; «Из шаблона ▾» открывает копию без имени, «Сохранить как шаблон» — выбор файла в `scripts/templates/`. Решение строителя: имя — через обычный выбор файла (не своё поле с проверкой), удалить свой шаблон — в файловом менеджере (правый щелчок в списке не сделан).
- `crt.Session.Connect` в ShagShell возвращает id новой вкладки (ошибка, если она не открылась: опечатка в имени сессии) — `each_host` работает с ней, а не с той, что впереди. `run(…, until=…)`: что ждать вместо приглашения (enable, conf t); не дождались — `TimeoutError`, хост в списке неудачных.

## Часть 4: как сделано (2026-10-27)
- `core::debugger::Debugger` (состояние запуска, тесты); `crt.py` при `SHAGSHELL_TRACE` — `sys.settrace` + `threading.settrace`, на каждую строку скрипта `Builder.Line`; стоп — `Builder.Paused` с переменными кадра (без модулей / функций / классов, `repr` ≤ 120 символов), ждёт «Продолжить» / «Шаг» / отмены.
- Окно слышит, где скрипт, не чаще раза в 100 мс; карта «строка → блок» снимается при «Запустить» (код того запуска).
- Решения строителя: галочки ⚙ — у вкладки (не в Config), обе включены; «Значения на блоках» — только на паузе (значение переменной, которую блок сохраняет); точки остановки пропадают при правке, меняющей места блоков (вставка, удаление, перенос, отмена).

## Разбор и генерация
- **Разбор `.py` → блоки** делает сам Python: `res/python/shag_parse.py` (запуск `python3 -I shag_parse.py`, файл на stdin) отдаёт JSON: дерево из `ast` + комментарии из `tokenize` (с номерами строк). Rust (`core::builder`) превращает JSON в ленту блоков. Свой парсер Python на Rust не пишем.
- Что становится блоком: вызов `crt.*` → блок команды; `x = <вызов crt / крупного блока>` → тот же блок с «сохранить в x»; `x = …` → «Переменная»; `if/elif/else`, `for`, `while`, `try/except/finally`, `with open(...)`, `def` → блоки со вложенной лентой; вызов своей функции → «Вызвать функцию»; комментарий → «Комментарий» (комментарий в конце строки или внутри многострочного выражения становится блоком-комментарием над своим оператором); `import`, `return`, `break`, `continue`, `global`, `x += 1` и всё прочее → «Свой Python» с текстом оператора (`ast.unparse`); вкладка рисует `import` / `return` / `break` / `continue` маленькими блоками по первому слову; тело из одного `pass` — пустая лента (генерация пишет `pass` в пустое тело).
- **Генерация блоки → `.py`** — на Rust в `core::builder`, детерминированно: выражения — как их пишет `ast.unparse` (кавычки одинарные), 4 пробела, одна пустая строка между блоками верхнего уровня там, где была. Свой Python вставляется как есть (с отступом уровня).
- Инвариант (тест на каждый файл `Example/` и на шаблоны): `parse(gen(parse(f))) == parse(f)` и `gen(parse(gen(x))) == gen(x)`; и Python-`ast` исходника и результата совпадают (без учёта форматирования) — проверка `ast.dump` в тесте через `python3`.

## Каталог блоков
- `core::builder::catalog` — один список: для каждого блока имя, группа, Python-шаблон, параметры (имя, тип, по умолчанию, обязательный, «ещё»), что возвращает, подсказка и пример en + ru (строки `fl!` или в самом каталоге — решение строителя; держать en и ru рядом).
- Тест: каждый публичный метод / свойство `crt.py` (список получает тест из `python3 -c` по `dir()` объектов) есть в каталоге, и наоборот.

## Шаблоны
- Всё хранится в одном месте — `~/.config/shagshell/scripts/` (решение пользователя, 2026-10-27; `/usr/share` не используем). «Из шаблона ▾»: файлы `scripts/templates/*.py` и `scripts/examples/*.py`. Три сценария из «Зачем» (`res/builder-templates/*.py`, вшиты через `core::bundled`) кладутся в `scripts/templates/`, только если такого файла нет: их можно править и удалять, удалённый вернётся при следующем запуске.
- «Сохранить как шаблон» — имя (проверка как у сессий) → файл в `scripts/templates/`. Удалить свой шаблон — правый щелчок в списке.
- Шаблон открывается новой несохранённой вкладкой.

## Запись (Script → Record Script)
- Stop записи открывает новую вкладку конструктора с записанным текстом (разобранным в блоки), без имени; сохранение — из вкладки. Прежний диалог сохранения (`App::save_recording`) больше не показывается.

## Сохранение
- Несохранённое отмечено в заголовке вкладки (•); закрытие несохранённой вкладки спрашивает «Сохранить / Не сохранять / Отмена». Без автосохранения (в отличие от заметок: скрипт сохраняется осознанно).
- Сохранённый скрипт — обычный `.py`: Button Bar, клавиши, планировщик, `--script`.

## Части (по PR, каждая — минорная версия)
1. `core::builder`: каталог, `shag_parse.py`, разбор и генерация, инварианты на `Example/`.
2. Вкладка: палитра, лента, перетаскивание, поля, шпаргалка, код (чтение + правка), открыть / сохранить.
3. `shag_blocks.py` и крупные блоки (включая параллель), шаблоны.
4. Запуск с подсветкой и отладка.
5. Запись сразу в блоки.

## Решения строителя (не согласованы с пользователем, можно поправить)
- Порядок частей и что войдёт в каждую.
- Точный набор и имена крупных блоков и функций `shag_blocks.py`.
- Горячие клавиши в ленте (Delete, Ctrl+C/V/Z) — не Ctrl+Insert / Shift+Insert.
- Точки остановки не сохраняются в файл.
- Нет автосохранения.
- Параллельно не больше 10 хостов сразу (поле на блоке).
- Где хранятся тексты подсказок каталога.
