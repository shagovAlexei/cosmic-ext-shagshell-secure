# 28. Pre-script сессии

Поле `pre_script` в файле сессии (Session Options → Connection → «Скрипт до подключения»).

## Что
- Запускается **до** ssh / telnet / оболочки, **без вкладки** (`crt.Screen.*` недоступен): можно спросить (`crt.Dialog`), поднять VPN, `ssh-add`, проверить хост (`os`, `subprocess`, `socket`). Аргументы: имя сессии, хост, пользователь.
- Закончился хорошо — вкладка открывается (и дальше запускается обычный `script` сессии). Упал, `sys.exit(1)` или остановлен — сессия **не открывается**, в строке состояния сообщение, ошибки в консоли скрипта.
- Работает там, где работает `script` сессии (двойной клик, Connect, Connect all, Quick Connect по сохранённой), а с 0.47.0 и для Reconnect / Clone вкладки сохранённой сессии (меню, клавиши, Enter на закрытой вкладке): сначала скрипт, потом команда; при неудаче вкладка остаётся как была. Не для «Открыть SFTP» и не для автопереподключения (оно не должно снова задавать вопросы).
- Пример: `Example/14_pre_script.py`.

## Как
- `Session.pre_script` (+ `Form`, тесты trim / запись только непустого); `Scripts::run` отдаёт id запуска, `Outcome.ended`; `App.pre_runs` держит ожидающее (`AfterPre`: новая вкладка с post-скриптом, либо Reconnect / Clone вкладки) до конца запуска. Reconnect / Clone сохранённой сессии идут через `Message::PreGate` → `App::pre_gate` → `Tabs::run_gated`.

## Не делаем
- Список скриптов на сессию; передачу результата pre-скрипта в сессию (например, выбранного хоста).
