# 14. X / Y / Zmodem в терминале

Передача файлов по самому соединению терминала (SSH, Telnet, Serial): на сервере `sz файл` / `rz`, у нас — как в SecureCRT. Работу делают программы из пакета **lrzsz** (`sz`, `rz`, `sb`, `rb`, `sx`, `rx`): своего протокола мы не пишем (как и SSH).

## Как это выглядит
- **Скачать (Zmodem, автоматически).** На сервере `sz файл…`. Начало передачи сервер сообщает строкой `rz\r**\x18B00…`; мы это замечаем в потоке, терминал замолкает, под строкой состояния «Zmodem: приём…» запускается `rz` в папке загрузок, файлы появляются там. По окончании — «Zmodem: получено N файлов» (или причина), терминал снова показывает вывод.
- **Закачать (Zmodem).** На сервере `rz`, у нас Transfer → «Отправить Zmodem…» (выбор файлов) — запускается `sz` с этими файлами.
- **Ymodem / Xmodem.** На сервере `sb` / `sx файл` (или `rb` / `rx`): Transfer → «Принять Ymodem…», «Принять Xmodem…» (спрашивает имя файла), «Отправить Ymodem / Xmodem…». Автоопределения нет (протокол не объявляет себя): сначала запускают программу на сервере, потом выбирают пункт.
- Папка загрузок: Options → Global Options → SFTP/Transfer, поле «Папка загрузок» (по умолчанию `~/Downloads`). Отмена: Transfer → «Отменить передачу» (шлёт серверу отмену CAN×8 и убивает локальную программу).
- Нет lrzsz — пункты меню серые, `shagshell --check` показывает `sz`/`rz` как MISSING (нужно для Zmodem; остальные не обязательны), автоприём не включается.

## Устройство
- Поток PTY читает `term::log::TapReader`. Пока передача идёт, он **не отдаёт байты терминалу, а пишет их в stdin локальной программы**; stdout программы (`sz`/`rz` говорит с сервером по stdout) идёт во вход PTY (`Tap::input`). Вызов `read` во время передачи возвращает `WouldBlock`, чтобы цикл терминала не посчитал это концом файла.
- `core::zmodem`: распознавание начала передачи (`ZRQINIT` / «rz\r» — сервер собирается слать; `ZRINIT` «**\x18B01» — сервер ждёт файл, для автозапуска не используется), сборка команд (`rz -y -b …`, `sz -b …`, `sb`, `rb`, `sx`, `rx` со своими флагами), разбор итоговых строк.
- Передача — одна на вкладку; новая, пока идёт старая, не начинается.

## Мои решения (проверь)
- Только lrzsz (системный), своих реализаций нет; `rz` с флагом `-y` перезаписывает совпавшие имена **нет** — по умолчанию `rz` не перезаписывает, а добавляет суффикс (так безопаснее).
- Автоприём только Zmodem; запуск `sz` по ZRINIT не делается (всегда ручной выбор файлов).
- Прогресс — число полученных/отправленных байт и скорость в строке состояния (по выводу `sz`/`rz` на stderr), без отдельной панели.

## Что можно проверить без lrzsz
Тесты в ядре: распознавание начала передачи в потоке (в том числе разбитое на куски), сборка аргументов. Подмена программы (`cat`) проверяет перенаправление потока туда-обратно. Сама передача с настоящим `sz`/`rz` — вручную (lrzsz на этой машине нет; на сервере чаще всего есть).
