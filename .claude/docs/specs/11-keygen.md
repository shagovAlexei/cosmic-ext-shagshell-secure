# 11. Создание ключей и загрузка на сервер

Tools → «Создать открытый ключ…» (как мастер Create Public Key в SecureCRT) и «Загрузить ключ на сервер…» (`ssh-copy-id`, SecureCRT: Public Key Assistant). Две части одного PR.

## Создание ключа
Окно (диалог в главном окне):
- **Тип:** Ed25519 (по умолчанию), ECDSA (256 / 384 / 521), RSA (3072 / 4096).
- **Файл:** `~/.ssh/id_<тип>` по умолчанию, можно изменить; существующий файл не перезаписывается (ошибка в диалоге, пока имя не сменят).
- **Комментарий** (по умолчанию `пользователь@хост`).
- **Парольная фраза** (дважды; пусто — без фразы, с предупреждением). Не пишется в файлы и логи, не попадает в аргументы процесса (`-N` виден в `/proc/<pid>/cmdline`): `ssh-keygen` читает её через `SSH_ASKPASS` (проверено: с `SSH_ASKPASS_REQUIRE=force` ssh-keygen спрашивает так же, как ssh). Askpass здесь — наш же бинарник в режиме «выдать фразу из переменной окружения процесса» (виден только владельцу).
- Кнопка «Создать»: запускается `ssh-keygen -q -t <тип> [-b <бит>] -f <файл> -C <комментарий>`; результат: путь к файлу и отпечаток (`ssh-keygen -lf`), открытый ключ показан в поле для копирования, кнопка «Копировать» кладёт его в буфер обмена. Права закрытого ключа 0600 ставит сам `ssh-keygen`.

## Загрузка на сервер (`ssh-copy-id`)
- Выбор сессии (ssh) и ключа (`~/.ssh/*.pub`); кнопка запускает во вкладке терминала `ssh-copy-id -i <ключ.pub> <опции сессии>` — пароль спросит обычный askpass (из keyring), результат виден в терминале. Никаких новых каналов секретов.

## Мои решения (проверь)
- Генерация только через системный `ssh-keygen`, своего кода криптографии нет.
- DSA и ed25519-sk (FIDO) не предлагаются.
- Связать ключ с сессией (поле «Файл ключа») после создания — кнопка «Использовать в сессии…» не делается; путь виден в диалоге, вписывается вручную.
