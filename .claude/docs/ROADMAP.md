Первоначальный набросок (решения — в спецификации):

Мини-приложение: скрипт собирается из блоков-команд мышью, без набора Python.

Как это видит пользователь:
- слева — список всех команд в виде блоков (палитра), с поиском и подсказкой к каждому;
- справа — окно скрипта, куда блоки перетаскиваются;
- блок — команда с параметрами (поля прямо на блоке).

Предварительные мысли о том, как устроить. Ничего не решено, сначала brainstorm:
- **Источник блоков — один список в core** (`core::script_blocks`). В нём каждая команда `crt`: имя, параметры (тип: текст / число / флажок / выбор из списка / сессия / файл, значение по умолчанию), что возвращает, подсказка RU+EN, пример. Из этого же списка можно генерировать справку и проверять, что `crt.py` знает все команды (тест).
- **Блоки, кроме вызовов `crt`:**
  - переменная («сохранить результат в …»);
  - «если» по результату (`WaitForStrings` → ветка на каждую строку, MessageBox → Да / Нет);
  - «повторить N раз», «для каждой строки списка / файла»;
  - пауза, комментарий;
  - «свой Python» — запасной выход для того, чего нет среди блоков.
- **Вид:** вертикальная лента блоков, как в Apple Automator / Shortcuts, а не свободный холст, как в Scratch.
  - Вложенность («если» / «повторить») — отступом и рамкой.
  - Перетаскивание из палитры в ленту и внутри ленты (у нас уже есть своя механика перетаскивания строк в дереве сессий).
  - Двойной щелчок по блоку в палитре добавляет его в конец ленты.
- **Результат — обычный `.py` для `crt`**, который можно запустить, повесить на кнопку или клавишу, отдать в SecureCRT.
  - Генерация в одну сторону: блоки → код.
  - Чтобы скрипт снова открывался в конструкторе, блоки хранятся рядом (JSON в комментарии в начале файла или файл `.blocks.json`).
  - Внизу — живой предпросмотр получившегося кода.
  - Кнопки «Запустить на активной вкладке», «Сохранить», «Открыть как текст» (в заметке).
- **Подсказки:** при наведении на блок — что делает команда, её параметры, пример; при ошибке в параметре — блок подсвечен красным, скрипт не запускается.
- **Открытые вопросы:**
  - окно или вкладка (как заметки);
  - разбирать ли существующие `.py` в блоки (скорее нет: только то, что сделано в конструкторе);
  - нужна ли запись (Script → Record) сразу в блоки.
